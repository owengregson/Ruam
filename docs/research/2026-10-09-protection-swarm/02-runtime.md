# S2 — Runtime execution architecture

Independent proposal, 2026-10-09. Recommendation: prototype S2-A with S2-B as its representation interface; neither presently establishes protection. All accepted execution is strictly offline, self-contained JavaScript. The objective is increased cost of an independently reusable recovered implementation. Unchanged artifact copying remains free of any analysis requirement.

## S2-A — Joint predicate-and-result region synthesis

**Mechanism.** Form compiler-proven, bounded regions containing several branches, joins and live outputs, rather than preserving every canonical branch boundary. Translate eligible semantics to an exact bitvector relation. Include exit selection and all outgoing values as joint outputs. Search equivalent implementations using word decomposition, predicate factoring, shared subexpressions and alternative evaluation schedules; verify each candidate against that relation. Emit one selected, straight-line or structured implementation directly, with no semantic selector, generic evaluator or per-operation wrappers.

For example, a branch that selects two different updates to a rolling integer state becomes one joint network producing the next state and exit condition. Shared terms must contribute to both actual outputs; introducing removable ballast earns nothing. Rewrite across authored operations before choosing temporary values, so instrumentation of every assignment need not reveal the original intermediates. Build variation chooses different verified dependency structures; shipping every equivalent realization is unnecessary and may hand attackers the easiest one.

**Hypothesis and strongest attack.** Larger joint relations can defeat the small expression windows used by synthesis attacks, but the attacker can repartition the emitted graph, solve bitvectors, infer invariants, or synthesize the whole function. [Syntia, USENIX 2017](https://www.usenix.org/conference/usenixsecurity17/technical-sessions/presentation/blazytko), demonstrates why syntactic complexity does not imply semantic complexity. [Loki, USENIX 2022](https://www.usenix.org/conference/usenixsecurity22/presentation/schloegel), motivates testing verified expression diversity against several attack families; its native-code results are not evidence for JavaScript. We borrow the experimental discipline, not its VM handler architecture.

An easier equivalent fallback defeats the proposal: a type guard that selects a plainly recoverable implementation gives the attacker a free alternate oracle. Evaluate every emitted lane, including out-of-domain behavior, under the minimum attack cost. Start with regions whose domains follow from program semantics, not optimistic user assertions.

**Semantics/cost.** Begin with exact Boolean/int32/uint32 operations, bounded loops and nonthrowing branches. Do not reinterpret floating-point addition as modular arithmetic or execute an untaken coercive branch. General values retain verified exact lowerings, and their coverage remains part of the public contract. Proposed prototype ceilings are 10× unprotected runtime and 15× source size on eligible kernels, with separate whole-program totals; compile-time solver cost is reported separately.

**Kill test.** Use 12 independently selected branch/state kernels, 20 builds each, with artifact-aware AST normalization, algebraic simplification, dynamic slicing, window synthesis and whole-function learning. Compare main max, repaired September, ordinary fused compilation and S2-A at equivalent coverage. Kill the protection hypothesis if a reusable attack reaches 95% held-out behavioral recovery with less than 3× the best baseline's attack CPU or analyst effort, or if the budgets fail. Thresholds are proposed investment gates, not security levels.

## S2-B — Escape-directed state fusion with projection-only effects

**Mechanism.** Discover closed clusters of authored closures and private objects. Scalarize only objects proven free of externally observable identity, accessors, reflection and escape. Then combine their private scalar state with continuation liveness across multiple effect regions. Choose a per-cluster invertible representation `E` and emit each actual transition directly as `E_next(F(E_prev^-1(state)))`, simplifying composition before code generation. Avoid materializing the complete decoded tuple; host operations open only their required argument projection at the lexical call/property site.

This is not threshold sharing: there are no extra charts, contributions or reconstruction quorum. Its proposed gain comes from eliminating real object/closure/region cuts and jointly rewriting necessary state updates. Vary scalar/bit decomposition and closure specialization across builds, while keeping each build's implementation static. Keep private state in activation-owned locals; suspension stores only live encoded values in activation-specific continuations.

**Hypothesis and strongest attack.** The attacker must reconstruct relationships across several continuations instead of hooking a reusable object handler or full-frame decoder. However, known local encodings can be symbolically inverted, host calls reveal exact arguments and effects, and scalar replacement may make recovery easier. This proposal deserves no credit merely for removing allocations. A separate plain-scalarization control is mandatory. Reference-valued identity cannot be hidden by renaming handles.

**Semantics/cost.** Any possible escape or reflective observation closes the cluster before transformation; do not speculate and restore an authored body. Unknown calls retain exact order and reentrancy semantics. Before a host call, commit state observable through reentrant closures; abrupt completion follows a separately verified successor. Preserve `normal`, `return`, `throw`, `break` and `continue`, including targets and `finally` override behavior, as required by [ECMAScript completion records, accessed 2026-10-09](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-completion-record-specification-type). Heap liveness and duplicated continuation code receive explicit budgets.

**Kill test.** Exercise closure-heavy parsers and state machines with getters, proxies, throws, nested callbacks and suspension adversaries. Any observable mismatch kills admission. Kill the protection component if complete private-state recovery stays within 2× the plain-scalarized control after AST/dataflow normalization, or if most regions immediately expose their whole live state at the host ABI.

## Integration and decision

Owner-only contracts should include `RegionContract {domainProof,effects,aliasEscapeFacts,liveIn,liveOut,completionEdges}`, `RepresentationPlan {physicalTypes,edgeTransfers,projectionSites}`, and `RealizationEvidence {equivalenceProof,resourceBounds,attackResults}`. None belongs in shipped reconstruction metadata.

Order: semantic ownership → effect/escape analysis → cluster formation → S2-A relation generation → S2-B representation composition → exact general lowering → independent equivalence and adversarial qualification → atomic publication. Dynamic source enters the same pipeline or fails before execution/publication according to the chosen deployment contract. ABI sites declare values, identities, timing/order and completions visible to the host; this leakage cannot be erased by runtime wrappers.

Retain canonical ownership, conservative effects, specialized emitters and honest refusal. Replace fixed two-region composition and array-based BPRF cut points. Defer general floating-point synthesis and cross-suspension fusion until the bounded offline tests survive. Historical custody results supply failure evidence only; custody is outside the system. Prefer one attack-qualified policy over separately toggled transformations. My confidence is moderate in implementability for restricted clusters, low in durable resistance to adaptive artifact-aware attacks.
