# Specialist 6: offline deployment and distribution integration

Independent round, 2026-10-09. This brief does not read peer proposals. Execution is strictly self-contained JavaScript: no service, remote secret, hardware custody, native component or WASM dependency. An attacker possesses every emitted file and can reuse the package unchanged. Module structure and randomized builds are not trust boundaries.

## Findings and limits

PR5's cohort digest is embedded into each member; it diversifies builds without requiring siblings. Its provider link writes a recoverable value through `String.fromCharCode`, while the shielded path skips the consumer fold entirely ([transform.ts:213–276, 430–440](https://github.com/owengregson/Ruam/blob/30f4563/packages/ruam/src/transform.ts#L213)). This is a concrete argument for one owner pipeline, not another linking flag. The source-map gate closes a real disclosure but starts from a copied tree ([source-map-gate.ts:4–13](https://github.com/owengregson/Ruam/blob/30f4563/packages/ruam/src/source-map-gate.ts#L4)); an allowlisted output package is easier to reason about than deleting leaks afterward.

The local-only September snapshot contains reusable graph machinery: `f7f52c8:packages/ruam/src/isogloss/runtime/module-graph-artifact-emitter.ts:110–117` owns protected edges and preserves native ESM cycle/TLA ordering; `:165–225` rejects authored-module escape through external boundaries. `module-graph-file-protection.ts:79–128,135–218` freezes source evidence, requires qualification and stages a sibling directory. Its two directory renames provide rollback but can expose a temporary missing target; they are not a universally atomic live-release switch. Individual-file publication is also not graph-atomic.

The dynamic-source ABI supplies named live-binding accessors (`f7f52c8:packages/ruam/src/isogloss/dynamic-source/deployment.ts:58–90`) and centrally invokes a parser/runtime (`:116–140`). This helps semantic ownership but supplies valuable analysis structure. A string entering that ABI is observable; protection cannot retroactively make the input unknown.

## S6-A: one graph-owned compilation and boundary plan

**Mechanism.** Expose one `protect({entrypoints, sources, hostContract, buildSeed, output})` operation. File and directory conveniences construct singleton or multi-module inputs for the same operation. Freeze the complete authored graph before selecting regions or layouts. Classify every executable source edge as protected authored code or declared host ABI; deny unresolved authored edges and partial publication. Resource files are explicit assets, not copied implicitly. Supplied application or vendor JS remains authored ownership even if called through an adapter; legitimate external host modules are separately inventoried platform capabilities, never an escape for supplied source.

Compute strongly connected module components and shared live-binding identities first. Allow control/data specialists to fuse private helper computations across module boundaries only when effect order, initialization, TDZ and namespace observations are proven preserved. Keep externally observable exports, module namespace identity, `import.meta` behavior and top-level-await dependency ordering faithful to the declared host. Emit private cross-module computations through the same regional compiler; do not make a per-file VM or provider/global slot a second compilation route.

**Possible protection contribution.** Whole-graph optimization can remove clean private API cuts and share semantic context across previously independently extractable units. That is a testable change to the analysis task; sprinkling a cohort hash is not. The attacker can still trace all actual calls and normalize the full graph, so no cryptographic or file-isolation claim follows.

**Interfaces/cost.** Produce `FrozenSourceGraph`, `ModuleCellContract`, `HostBoundaryInventory`, `RegionPlan` and `ArtifactPlan`. Pass a sealed policy object to every emitter; it cannot silently choose a less protected backend. Reject unresolved dynamic edges before publication. Cap graph memory, specialization growth and incremental invalidation; a one-file change may legitimately rebuild its semantic component. Avoid meaningless global coupling that forces every package change to rebuild everything.

**Experiment/kill.** Compare identical programs protected per-file and graph-owned with equal operation coverage, size budget and runtime budget. Attack with whole-package static extraction, boundary logging and unchanged package reuse. Reject cross-module fusion as a protection feature if a generic normalizer recovers the same private call graph with under 2× attack cost. Any cycle, live-binding or initialization-order mismatch vetoes the transformation; retaining graph ownership as correctness infrastructure remains worthwhile.

## S6-B: artifact-only publication with reproducible qualification

**Mechanism.** Build into an empty staging package containing only inventoried generated scripts and approved nonexecutable assets. Source, source maps, semantic IR, owner traces, original names, seed ledgers and coverage sidecars live outside the publication tree. A small public manifest may identify exact output hashes and declared host requirements, but must not enumerate source-to-region correspondences, semantic opcodes or reconstruction paths. The certificate is build evidence, not a secret or attacker-enforced authorization token.

Emit, parse, inventory and qualify the exact final bytes after minification. Publication is the sole terminal stage: compile → graph qualification → artifact inventory → package qualification → commit. A failed shard cannot fall back to plaintext or an old native artifact. For one-file output, stage then rename. For module packages, publish an immutable versioned package and switch a single entry artifact whose imports pin that version; alternatively publish one immutable archive. Preserve old version paths for already-running imports. Do not describe multiple replacements as atomic merely because each uses rename.

**Entropy.** Retain the labeled entropy interface (`f7f52c8:packages/ruam/src/random/entropy.ts:14–55`), but derive deterministic streams from stable graph/node identities rather than traversal order. Record tool versions, policy and seed privately for reproducibility. Diversity is measured with the root seed disclosed to the attacker; its secrecy is not part of the model. Randomization must not perturb JS evaluation order or qualification coverage.

**Attack/cost.** This eliminates accidental bypasses and analyst sidecars, not semantic recovery from generated JS. Attackers may extract every support file, replay prior builds and patch the manifest. Build-time hashing and staging add linear I/O; runtime overhead should be negligible. Content-addressed filenames can reveal equality across releases, which is acceptable because they are not protection secrets.

**Experiment/kill.** Fault-inject compiler failure, map leakage, unreadable input, symlink/path escape, source mutation between reads, partial writes, disk-full and interrupted commits. Assert the previous complete package remains usable or the new complete package becomes visible; never a mixed authored/protected graph. Compare shipped inventory with the owner ledger. Any plaintext fallback, published owner trace or mixed-version import vetoes release. Retain this component as mandatory hygiene even if attacker recovery cost is unchanged.

## S6-C: one enforceable ingress, reflection and CSP contract

**Mechanism.** The graph plan inventories every source-producing capability: direct/indirect eval, constructors reached through aliases, string timers, dynamic imports and host-created code. Build-time-known source can be compiled into the protected graph while preserving its scope/effect contract. The initial qualified profile accepts only finite, proven source alternatives compiled ahead of time; unknown or unbounded runtime source ingress is rejected before publication. Never silently delegate to native eval/Function. An arbitrary-source offline interpreter is deferred research, not another shipping mode: it recreates a generic semantic machine and cannot borrow the static-regional resistance score.

Strict CSP blocks host string compilation through the specified hook; a custom parser/interpreter is an implementation approach, not permission to change the application's original CSP-visible behavior. See [CSP3 §4.4.1](https://www.w3.org/TR/CSP3/#can-compile-strings), checked 2026-10-09. A blanket “all JavaScript, exact behavior, every CSP” promise is therefore inadmissible.

**Reflection boundary.** Exact authored `Function.prototype.toString()` conflicts with hiding authored source: the standard returns available source text ([ECMA-262 §20.2.3.5](https://tc39.es/ecma262/multipage/fundamental-objects.html#sec-function.prototype.tostring), checked 2026-10-09). Proposed product contract: execution/identity semantics are preserved for admitted programs; reflected source describes the generated artifact. Programs whose functional behavior requires original-source reflection must be rejected unless the user explicitly accepts source disclosure. Do not patch intrinsics and claim transparent equivalence. Preserve required function names, lengths, prototypes and receiver behavior where admitted, recognizing their ABI leakage.

**Interfaces/attacks/cost.** `HostContract` and `SourceIngressPlan` feed the same graph, boundary and publication stages. Intrinsic capture is compatibility plumbing, not trust against preload edits. An attacker can hook ingress, steal lexical carrier accessors, or invoke captured capabilities directly. Do not ship a parser/interpreter in the initial qualified profile; precompiled finite ingress must not introduce a generic operation dispatcher.

**Experiment/kill.** Exercise aliased constructors, coercion side effects, reentrant eval, cyclic dynamic imports, external host callbacks, native toString borrowed across realms and CSP violations. Require either contract-faithful execution or a prepublication rejection. A production artifact that retains authored bodies, slips through an unclassified source sink, or changes a claimed observable fails. Any proposed later dynamic interpreter that becomes a universal recovery adapter for static regions is rejected; arbitrary runtime JS support remains explicitly unqualified.

## Recommendation

Adopt S6-A/B as the single pipeline and S6-C as its explicit admission boundary. Prototype cross-module semantic fusion only after differential attacks; treat packaging safeguards as hygiene. Reuse WIP ownership/publication ideas after repairing and qualifying them. Remove cohort-secret rhetoric, optional bypass paths and unqualified native fallbacks. Nothing in this deployment plan converts offline JavaScript into a trusted execution environment.
