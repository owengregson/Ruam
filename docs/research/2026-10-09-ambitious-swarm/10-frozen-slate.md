# Ambitious architecture slate r1

Frozen after three independent candidate sets (eight coordinator, eight B, seven C nominations) and actual A/B/C argumentation. There were **23 nominations with substantial overlap**, not 23 independent new mechanisms. This vote selects at most two research ideas; it does not approve implementation or claim improved protection.

## A1 — Replace the algorithm and maintain only necessary derived state

One composite architecture, combining B1/B2/R1 with supporting specialization and shared-consumer ideas. A source-defined stateful evaluator is compiled into a genuinely different algorithm family: specialized decision/dataflow networks, indexed relational computation, or jointly maintained derived views across real events. The private source's helper layout, repeated scans, configuration tables and dispensable state representation cease to be runtime structures.

This is more ambitious than local branch folding or renaming operations. Compilation must change the application algorithm and the relationships between initialization, updates and outputs. It emits one ordinary JavaScript realization, with native effect boundaries, no generic VM, no secret and no second direct implementation. The entire package and all compiler recipes remain available to attackers.

**The objective for this track:** increase the cost of accurately explaining a private rule and making a specified partial rule change while preserving all other hidden behavior and future histories. Functional replacement remains separately measured under the earlier protocol. There is no current argument that a clean state-machine lifter cannot clone this design cheaply. Its difficulty must never be inferred from failing to reproduce original variable names, original algorithms or discarded irrelevant source details.

The first admission profile requires an existing deterministic synchronous event API; owned initialization/reset; exact source-established numeric and collection semantics; and private, nonescaping state. Freeze duplicate multiplicities, iteration order, deletion semantics, observable identity and exceptions. A delete-by-key or export-record API may require original records to remain. Do not change the API to get rid of them, and do not claim they disappeared if they remain. Bounds come from source semantics; failure to establish them rejects the candidate.

**Shared implementation path if separately funded:** recognize one eligible domain with checked rules; build its exact transition/output relation; retain alternatives from genuinely different algorithm families; remove only proved unobservable state; specialize initialization, events and consumers together; use one cost planner and direct JS emitter; validate final behavior; then run attack qualification. The current PR's narrow AST recipes are useful test infrastructure, not an implementation of this architecture.

**Mandatory first adversaries:** a clean transition extractor; algorithm recognition and invariant inference; full reset/replay and chosen histories; omission/synthesis/remapping of events; and a sidecar/shadow evaluator constructed from public event history plus the edit ticket. Attackers may retain every derived field, add new state, patch outputs, rebuild the evaluator or ignore the apparent intended decoding route. A complete replacement specification in a ticket often makes the sidecar trivial; the ticket audit must disclose that, not hide public information. A partial ticket gives the same information for ordinary and transformed implementations, requiring unspecified private behaviors to remain correct on both.

Begin with three **existing** evaluator roots and three applicable algorithm families, admitting failures honestly. Give identical task information and resources to both sides. Explain tasks must predict effects/invariants on held-out histories; edit tasks must pass hidden untouched-behavior, cold-start, reset, deletion, duplicate and boundary tests. Record CPU, wall time, model use, analyst work, tool setup/transfer and legitimate execution/size/memory cost separately. If a reusable sidecar, replay strategy or extractor solves the tasks at comparable cost, stop. Do not turn an edit-only result into a broad anti-cloning or cryptographic claim. Only survivors justify a larger preregistered study under the prior design's cost envelope.

## A2 — Whole-relation circuit resynthesis

C2/B4/R4: synthesize an entire exact bounded integer relation across source operation cuts into direct bit-level/word-packed JS. Distinct obstacle: meaningful word-level relation recovery and targeted edits, rather than original source boundaries. Cheapest defeat: extract and simplify the whole network or patch its projections. Circuit extraction counts when it removes realization machinery and yields a usable independent model; cosmetic reprinting does not. Legitimate circuit expansion may overwhelm any attacker burden. C could not supply a concrete noncryptographic kernel/edit surviving the first cheap defeat and withdrew its second-slot nomination. Voters may still select it only with a concrete reason to reverse that decision.

## A3 — Future-behavior residual graph

C1/B3/R2: compile proven equivalent future behaviors into a residual transducer, eliminating irrelevant original state distinctions. Cheapest defeat: extract or learn the already minimized graph. This often assists functional reconstruction; history count is coverage, not hardness. Any useful residualization can support A1 without occupying another architecture slot. C withdrew its standalone nomination after argumentation.

## Alternative: select none

The candidate set has not demonstrated substantial protection. It is valid to decline architecture investment and retain only correctness/evaluation work until a real workload defeats the cheap attacks. No second idea must be manufactured to fill a quota.
