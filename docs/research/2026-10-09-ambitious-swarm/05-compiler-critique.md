## A concrete composite worth trying to disprove

Use an existing synchronous eligibility/pricing evaluator with a finite record schema and real insert, remove and update events. Its outputs must include several genuinely coupled totals, eligibility results and selected records. One source implementation repeatedly scans records; alternative implementations use indexed partitions and jointly maintained aggregate views. A third implementation can use a decision network only if the source's predicates actually admit that representation. Do not manufacture three unrelated implementations and call them algorithmic diversity.

The public contract includes input domain, duplicate-key behavior, insertion order, numeric overflow, missing-value behavior and exceptions. The compiler owns initialization, every update and every observation. It must not retain a cold direct scan that computes the same protected behavior. Any bulk-load path, reset/export/import interface or callback is part of the artifact and the attack. If original records remain present to satisfy an observation, the proposal may lose much of its premise; report that loss rather than hiding the interface.

For the first prototype, use authored Number-forcing integer operations and immutable primitive record fields, not speculative coercion guards. Preserve JS evaluation order at the admission boundary. A `>>> 0` result proves a Number value on normal completion; generic `~x` does not exclude BigInt. Similarly, a Babel binding marked constant is insufficient proof for sloppy `var` or Annex B block-function mutation. The current implementation's actual default-parameter and Annex B counterexamples illustrate why syntactic optimism cannot substitute for a semantic contract.

Keep mutable state private and use ordinary native closures initially. A qualified callback must observe committed values at its original call point; after a callback, any potentially aliased cache needs invalidation or rereading. The pricing prototype should instead begin with a callback-free transaction API and explicitly reject sources requiring callbacks within transactions. That stage boundary is a support limit, not a security gain. DOM adapters and imported vendor contributions remain owned even when their surrounding general code is not credited with the regional mechanism's strength.

The build can use browser-compatible JavaScript tooling, fixed algorithm recipes, source-side proof records and differential checks. There is no need for a novel runtime interpreter, solver, secret, persistent service or covert evaluator. A typed domain IR is justified by the exact contract; it must not be presented as general-JavaScript SSA or an automatic proof for arbitrary host integrations.

## Cheapest decisive experiment

Freeze twelve existing evaluator roots before transformation, preserving easy controls and rejected cases in the support table. Begin with three roots to debug the protocol, then freeze the held-out set without choosing only the ones that looked hard. Give the attacker the full artifact, compiler, seed, algorithm-family metadata available from source, and chosen event/reset access.

First implement a generic transition extractor that removes the candidate's realization machinery and emits a usable state-machine evaluator, retaining every necessary materialized view, initialization rule and output projection. This is a valid machine replacement even if it retains more state than necessary; it must expose executable transition semantics rather than merely rename variables or reprint the same AST as SSA. Separately record unchanged artifact reuse and cosmetic reprinting. Conversely, do not dismiss a successful clean evaluator as reuse just because it preserves the transition equations. If the lifter runs in approximately linear artifact time and passes hidden histories, the **functional replacement hypothesis fails**. Do not spend a second month trying to reconstruct original field meanings.

Then evaluate explicit edit tickets: change one eligibility rule, revise one discount interaction, or alter one duplicate-record policy. A successful edit must pass hidden long histories, resets, deletions, duplicate keys, cold initialization and boundary inputs. Establish the ordinary implementation's task cost first. Permit rebuilding the whole evaluator, a symbolic learner, output patching, and model-assisted domain recognition. Compare the minimum successful lane, amortizing one extractor across other algorithm families and held-out applications.

A provisional prototype stop rule is intentionally cheap: stop a variant after a reusable lifter yields correct functional replacements for all three pilot roots within twice the ordinary normalized-code effort, or after targeted edits take no more than twice ordinary median effort on all three. Treat these as engineering falsifiers, not statistically supported security multipliers. If the edit hypothesis survives, preregister a larger study and legitimate cost bounds before producing a positive claim. Report output bytes, cold initialization, per-event tails, peak state size and compile time; reduced scan time does not excuse unbounded indexes or slow cold paths.

## C03 critique and the strongest attack on the surviving nomination

I read C03 fully and challenged C directly on its two proposed spikes. C1 merges future-equivalent states and emits residual transitions; that overlaps R2/B3 and can hand the attacker a simpler machine. Its proposed two thousand possible histories are test coverage, not complexity: a one-state machine can accept arbitrarily many histories. C2 globally resynthesizes a bit circuit, overlapping R4/B4; a clean circuit/cut extractor can produce a usable behavioral explanation or implementation without reconstructing the author's word-level arithmetic. Neither needs to recover source-operation partitions to defeat the original replacement objective.

C replied that it could not name an existing C1 or C2 task surviving those cheap defeats, explicitly withdrew both as second-slot nominations, and accepted that neither history count nor distinguishable-state count proves hardness. C's fixed-word edit motivation for C2 remains an untested hypothesis, not a reason to spend the second slot. I therefore retain only the single B1+B2 composite nomination, conditionally and before any ballot.

C also contributed the strongest challenge to that composite: an attacker can observe the entire public event stream, retain original tuples in its own added state, and implement the revised rule directly from the edit ticket and public schema. It need never discover the protected program's maintained-view invariants. This is permissible independent reimplementation, not a violation of the attack model. Reset/replay, snapshots, added memory, fresh indexing and replacing the entire evaluator must be allowed and charged at their actual cost.

The test design must therefore separate information required to specify the desired edit from a ticket that accidentally gives away a full original rule program. Preassign normal maintainer-facing edits without presenting owner source or recovered view formulas, but do not hide public schema or event semantics that a real attacker has. Measure a ticket-driven shadow implementation first, alongside circuit/state-machine extraction and invariant recovery. If the shadow implementation passes all required observations and histories cheaply, the claimed edit obstacle fails even if residual-state interpretation is difficult. Requiring an attacker to edit the emitted implementation in place would manufacture the result.

For comprehension, require a checkable explanation of the actual original observable rule interactions, with adversarial counterexample questions and consequence predictions; accept a different correct model of those interactions. Exact attribution of a non-identifiable source algorithm cannot be the success condition. Score comprehension and correct edits separately and report cheap cloning/reuse independently. Neither a plausible prose summary nor an incorrect patch passing a few examples qualifies. There is still no measured positive result for the one nominated design.
